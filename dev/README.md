# dev/

Verification harness. Nothing here is needed to run the app — it exists so you can
prove the app works, and demo it, without spending money on the OpenAI API.

Run everything from the project root with the virtual environment's Python.

## The idea

Only the two network calls are ever faked:

- `vectorstore.embed_texts` — replaced with a deterministic hashed bag-of-words,
  so similar text still lands near similar text.
- `rag._openai()` — replaced with a canned completion.

Everything else in these runs is the real code: real Chroma reads and writes, real
FastAPI routes, real static files. That means these scripts prove the *wiring*.
They cannot prove *retrieval quality*, because a toy embedding does not understand
meaning. Quality needs a real key.

Each script writes to its own throwaway database (`dev/chroma_*`) and deletes it
afterwards, so your real library in `data/` is never touched.

## Scripts

| Script | What it proves |
|---|---|
| `make_test_pdfs.py` | Builds the fixtures in `dev/pdfs/` from scratch |
| `check_vectorstore.py` | Chroma wiring: metadata typing, result shape, distance to score, upsert, delete |
| `check_rag.py` | Prompt assembly, passage numbering, the empty and no-match paths |
| `check_api.py` | Every endpoint and every status code |
| `check_ingest_cli.py` | `scripts/ingest.py` end to end, including the error exits |
| `acceptance.py` | The full section 15 checklist, 51 checks |
| `demo_server.py` | Runs the real app with a seeded library, for demos |

## Usage

```powershell
.\venv\Scripts\Activate.ps1

python dev\acceptance.py          # the one to run if you only run one
python dev\check_api.py
python dev\check_vectorstore.py
python dev\check_rag.py
python dev\check_ingest_cli.py
```

Rebuild the test PDFs (they are committed, so this is rarely needed):

```powershell
python dev\make_test_pdfs.py
```

`locked.pdf` is password protected and cannot be regenerated by that script alone —
it is produced by re-encrypting `beacon.pdf`:

```powershell
python -c "from pypdf import PdfReader, PdfWriter; r=PdfReader('dev/pdfs/beacon.pdf'); w=PdfWriter(); [w.add_page(p) for p in r.pages]; w.encrypt('secret'); f=open('dev/pdfs/locked.pdf','wb'); w.write(f); f.close()"
```

## The demo server

Runs the real interface with a library already loaded and a fixed, sensible answer.
No API key, no cost, no network — good for recording a demo or showing someone the
citation behaviour.

```powershell
python dev\demo_server.py          # http://127.0.0.1:8011
python dev\demo_server.py 8020     # a different port
python dev\demo_server.py --xss    # also seed a hostile filename, to show escaping
```

The answer it returns is always the same, and it cites [1], [2] and [3] — enough to
demonstrate the margin and the click-through.

## The fixtures

`dev/pdfs/` holds four generated PDFs. They are not real papers; they are written to
exercise specific code paths.

- `lantern.pdf` — 9 pages, a plausible fake paper about a "gated retrieval"
  architecture. Contains deliberate end-of-line hyphenation (`recur-\nrence`) so the
  de-hyphenation in `clean_text` is actually tested.
- `beacon.pdf` — 3 pages, a second paper so the library has more than one document.
- `scanned.pdf` — pages with no extractable text, standing in for a scan.
- `locked.pdf` — password protected.
